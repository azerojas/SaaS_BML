# Contrato auditado — Fase 2

Fuente: Django views, serializers, selectors y servicios reales. No se presuponen rutas `/api/v1/`. Fase 1 tiene sesión/MFA/CSRF reales, 19 unit tests y build inicial aprobados. No se actualizan versiones principales. Los auxiliares references/templates indicados por la skill no se suministraron; prevalecen el código y los requisitos explícitos.

Paginación real: `{count,next,previous,results}`, page/page_size (máximo 100). Búsqueda `search` hasta 200 caracteres, acentos normalizados en servidor. Clientas: `activa=true|false|all`, orden apellido/nombre/id. Catálogo: `activo`, `visible_catalogo`, `categoria` ID; artículos `tipo`. Orden fijo orden/nombre/id; `ordering` se rechaza. Categorías de artículo y unidades no tienen estado ni DELETE. UI no inventará estas acciones.

Errores reales: 400 `{code:validacion,detail,errors}`, 409 duplicado/teléfono/SKU/slug/unidad en uso, 403 sin sesión o permiso/CSRF, 404, 429. Importes y cantidades se envían como cadenas decimales. Slug existente inmutable; generado por Django si se omite al crear. Receta reemplaza todas las filas en una transacción, costo_estimado=null; no descuenta stock. Principal de imagen es único; al eliminar se elige la primera restante en servidor. No existe subida multipart ni historial clínico/ficha adicional; ficha corresponde al detalle de Clientas, sin consultas financieras en esta fase.

Adaptaciones autorizadas por el alcance funcional: configuración de presentación sin secretos y PATCH de URL/alt/orden de imagen, conservando propietario y principal. No hay migraciones ni cambios de tablas. Dominios de imágenes y aviso de privacidad se toman del backend; si no están configurados se bloquea la operación dependiente y se informa, sin datos inventados. Las operaciones de aceptación usan PostgreSQL efímero, nunca crean clientas o catálogo en Lasheo real.
